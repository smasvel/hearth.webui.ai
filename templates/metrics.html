Live developer logs

Timestamped request lifecycle logs, updated every second and retained for two days — Hearth chat, plus any named client (including market_analysis) going through Lemonade or FastFlowLM. Active rows update token counts and throughput in place; completed and failed rows remain available for diagnosis. Streaming tokens right now are visible for Hearth chat, plus OpenCode/Continue traffic through Lemonade or FastFlowLM (their LAN-facing shims report it directly). LM Studio/vLLM/ KoboldCPP LAN traffic still has no per-token visibility at the proxy layer, see Help. Each row also shows whether it's actually running on the NPU — Lemonade serves several non-NPU recipes too (llamacpp/GGUF, whisper, embeddings), so a model's name alone isn't a reliable signal (confirmed live: a Lemonade model literally named "...-Coder-NPU" turned out to be a plain GGUF/llamacpp model).
